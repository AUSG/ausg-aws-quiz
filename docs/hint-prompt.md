# 힌트 작성 브리프

문항의 `hint` 필드를 새로 쓰거나 고칠 때 쓰는 문서다.

- 문항 원본: [`src/data/questions.ts`](../src/data/questions.ts)
- 검증 규칙: [`src/data/validateBank.ts`](../src/data/validateBank.ts)
- 현재 구성: AUSG·AWSKRUG·함께하기·AUSGCON 2026, 총 38문항

문항과 정답은 `questions.ts`를 직접 읽는다. 이 문서에 문제 표를 복사해 두지 않는다.
중복 사본은 문제 은행이 바뀔 때 가장 먼저 낡기 때문이다.

---

## 여기부터 복사 ↓

당신은 AUSG와 AWSKRUG 커뮤니티 부스에서 쓰는 3~5문제 퀴즈 앱의 힌트를 씁니다.
`src/data/questions.ts`의 문항을 읽고 각 문항의 힌트를 작성해 주세요.

### 이 힌트가 놓이는 자리

방문자는 행사장에 서 있고, 태블릿을 집어 든 지 1분 안에 떠납니다. 문제를 보고
답을 모르겠다 싶으면 그냥 내려놓습니다. 힌트는 그 사람을 붙잡는 짧은 실마리이지
정답 공개가 아닙니다. 채점에도 영향이 없고, 사용 기록도 남지 않습니다.

화면에서 힌트는 `Codex` 라벨과 함께 나옵니다. 옆에서 조수가 한마디 거들어 주는
느낌이면 맞습니다. 문제를 다시 설명하거나 훈계하는 말투는 피하세요.

### 반드시 지켜야 하는 규칙

1. 공백과 문장부호를 포함해 **45자 이하**로 씁니다.
2. 4지선다 문항의 정답 보기 문구를 그대로 넣지 않습니다.
3. O/X 문항도 `맞아요`, `아니에요`, `O`, `X`처럼 답을 직접 드러내지 않습니다.
4. 한 문장, 부드러운 `~해요` 체로 씁니다.
5. 문제 문장을 반복하지 말고, 기억을 꺼낼 실마리 하나만 줍니다.
6. 행사 방문자가 AUSG나 AWSKRUG를 처음 들었어도 이해할 표현을 씁니다.
7. `sourceUrl`은 사실 검증 근거이므로 힌트 작업 중 임의로 바꾸지 않습니다.

### 예시

| | 내용 |
|---|---|
| 문항 | `AUSG의 U가 뜻하는 단어는?` |
| 정답 | `University` |
| 나쁜 힌트 | `U는 University예요.` — 정답을 그대로 공개함 |
| 좋은 힌트 | `풀네임에서 학생 앞에 붙는 단어를 떠올려요.` |

| | 내용 |
|---|---|
| 문항 | `AWSKRUG는 학생이 아니어도 참여할 수 있을까요?` |
| 정답 | `O` |
| 나쁜 힌트 | `맞아요, 누구나 참여해요.` — 정답을 사실상 공개함 |
| 좋은 힌트 | `특정 학교나 직장에 소속될 필요가 없어요.` |

### 출력 형식

문항 ID마다 한 줄씩, 다른 설명 없이 다음 형태로만 출력합니다.

```text
aus-basic-01: 힌트 문장 (글자 수)
aus-basic-02: 힌트 문장 (글자 수)
```

45자를 넘긴 줄은 스스로 줄이고 다시 셉니다.

## 받은 힌트를 반영하는 방법

1. `src/data/questions.ts`에서 해당 문항의 `hint`만 교체한다.
2. `npm test`로 길이·정답 노출·출처·폰트 커버리지를 확인한다.
3. 새 한글 글자가 생겨 폰트 테스트가 깨지면 `python3 scripts/build-fonts.py`를 실행한다.
4. `npm run build`가 통과하는지 확인한다.
