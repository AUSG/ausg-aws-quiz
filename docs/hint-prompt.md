# 힌트 작성 브리프

문항의 `hint` 필드를 새로 쓰거나 고칠 때 쓰는 문서다.
아래 **「여기부터 복사」** 구간을 통째로 Claude(또는 Codex)에 붙여넣으면 된다.

- 문항 원본: [`src/data/questions.ts`](../src/data/questions.ts) — 커뮤니티 블록은 21행부터
- 규칙의 최종 출처: [`src/data/validateBank.ts`](../src/data/validateBank.ts).
  이 문서와 어긋나면 코드가 맞다.

## 여기부터 복사 ↓

당신은 AWS 커뮤니티(AUSG) 부스에서 쓰는 3문제 퀴즈 앱의 힌트를 씁니다.
아래 문항 표를 보고 각 문항의 힌트를 작성해 주세요.

### 이 힌트가 놓이는 자리

방문자는 행사장에 서 있고, 태블릿을 집어 든 지 30초 안에 떠납니다. 문제를 보고
답을 모르겠다 싶으면 그냥 내려놓습니다. 힌트는 **그 사람을 붙잡는 밧줄**이지
정답 공개가 아닙니다. 채점에도 영향이 없고, 힌트를 썼다는 기록도 남지 않습니다.

화면에서 힌트는 `Codex` 라벨과 함께 나옵니다. 옆에서 조수가 한마디 거들어 주는
느낌이면 맞습니다. 문제를 다시 설명하거나 훈계하는 말투는 맞지 않습니다.

### 반드시 지켜야 하는 규칙

어기면 `npm test`가 깨집니다.

1. **45자 이하.** 공백·문장부호 포함, 한글 한 글자를 1자로 셉니다.
   레이아웃 제약이라 넘기면 작은 폰에서 스크롤이 생깁니다.
2. **정답 보기의 문구를 그대로 넣지 마세요.** 4지선다 문항은 정답 보기 텍스트가
   힌트에 부분 문자열로라도 들어 있으면 검증에서 걸립니다.
   (O/X 문항은 이 검사에서 제외됩니다.)
3. **비워 두지 마세요.** 모든 문항에 힌트가 있어야 합니다.

### 문체 규칙

4. **한 문장, `~해요` 체.** 기존 힌트와 톤을 맞춥니다.
5. **개념만 상기시키세요.** 답을 알려주는 게 아니라, 아는 사람이 "아 그거"
   하고 떠올릴 실마리를 줍니다.
6. **비전공자 기준으로 쓰세요.** 방문자 상당수는 AWS를 처음 듣습니다.
   설명에 또 다른 전문 용어가 필요하면 그 힌트는 실패입니다.
7. **문제 문장을 다시 쓰지 마세요.** 방금 위에서 읽은 문장입니다.

### 예시

| | |
|---|---|
| 문항 | `EC2를 약정 없이 실행한 시간만큼 내는 기본 요금제는?` (정답: 온디맨드) |
| ❌ | `정답은 온디맨드예요.` — 정답 문구가 그대로 들어감 (규칙 2) |
| ❌ | `EC2 인스턴스 과금 모델 중 선불 약정이 없는 유형을 고르세요.` — 문제 재서술, 용어 추가 |
| ✅ | `약정도 선불도 없이, 쓴 시간만 계산하는 기본값이에요.` |

O/X 문항은 정답이 한 글자라 규칙 2가 적용되지 않지만, `O예요` 같은 힌트는
그 자체로 정답 공개이므로 쓰지 않습니다.

| | |
|---|---|
| 문항 | `AWS Lambda는 서버 프로비저닝 없이 코드를 실행한다?` (정답: O) |
| ❌ | `맞아요, O예요.` |
| ✅ | `'서버리스'라는 말이 무슨 뜻인지 떠올려 보세요.` |

### 출력 형식

문항 id마다 한 줄씩, 다른 설명 없이 이 형태로만 주세요.

```
cmu-01: 힌트 문장 (39자)
cmu-02: 힌트 문장 (34자)
```

글자 수는 직접 세어 괄호에 적어 주세요. 45자를 넘긴 줄이 있으면 스스로 줄여
다시 세어 주세요.

### 문항 표

정답은 **굵게** 표시했습니다. 현재 힌트가 있는 문항은 그것을 개선하거나,
더 나은 접근이 있으면 새로 써도 됩니다.

## 받은 힌트를 반영하는 방법

1. `src/data/questions.ts`에서 해당 문항의 `hint` 필드를 교체한다.
2. `npm test` — 길이·정답 노출·폰트 커버리지가 여기서 전부 걸린다.
3. 한글 글자가 새로 들어와 `fontCoverage` 테스트가 깨지면:

   ```bash
   python3 scripts/build-fonts.py
   ```

   그리고 `public/fonts/` 변경분을 함께 커밋한다.
4. `npm run build`가 통과하는지 확인한다.
