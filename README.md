# AWS 상식 퀴즈

대학생 해커톤 **부스용** AWS 퀴즈. AWS를 전혀 몰라도 풀 수 있는 난이도로, 한 명당 5문제 약 50초.

- **운영 URL**: https://ausg-aws-quiz.vercel.app *(배포 후 확정)*
- 백엔드 없음. 순수 정적 SPA라 **첫 로딩 후에는 네트워크가 끊겨도 계속 동작**한다.
- 개인정보를 일절 수집하지 않는다.

---

## 이 앱이 일반 퀴즈 앱과 다른 점

부스는 공부 도구가 아니다. 모르는 사람이 지나가다 태블릿을 집어 들고 50초를 쓰고 떠난다.
설계가 이 전제 위에 서 있으므로, 고치기 전에 아래를 먼저 읽을 것.

| 결정 | 이유 |
|---|---|
| **제출 버튼이 없다** — 보기를 누르면 즉시 채점 | 문항당 탭 3회 → 2회. 5문항이면 5번의 탭이 줄어든다 |
| **난이도가 오름차순** (1→1→2→2→3) | 1번에서 틀린 방문자는 태블릿을 내려놓는다. 이걸 막는 게 최우선 |
| **카테고리를 겹치지 않게 분산** | 순수 랜덤이면 네트워킹만 5문제가 나올 수 있다 |
| **틀려도 정답이 초록으로 켜진다** | 시험이 아니라 알려주는 것이 목적 |
| **결과 화면 배너가 가장 크다** | 스태프가 2m 밖에서 배너 **색**만 보고 상품 여부를 판단한다 |
| **60초 무입력 시 자동 리셋** | 다음 방문자가 앞사람 점수를 보는 걸 막는다 |
| **제목이 "AWS 상식 퀴즈"** | "CLF-C02"라고 쓰면 자격증 시험으로 읽혀서 지나가던 사람이 도망간다 |

## 현장 튜닝 (재배포 없이)

URL 파라미터로 바꾼다. 대기줄이 생기면 3문제로 내려서 처리량을 두 배로 만든다.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `?n=` | 5 | 문항 수 (3~10으로 제한) |
| `?prize=` | 4 | 상품 커트라인 (문항 수를 넘지 못함) |
| `?idle=` | 60 | 자동 리셋 초. `0`이면 끔 |
| `?kiosk=` | 1 | `0`이면 키오스크 모드 해제 |

```
https://ausg-aws-quiz.vercel.app/?n=3&prize=2     ← 줄이 길 때
https://ausg-aws-quiz.vercel.app/?idle=0          ← 무대 시연 등 자동 리셋이 방해될 때
```

> `?n=3`으로 내리면 커트라인 기본값 4가 자동으로 3까지 내려간다.
> (그대로 뒀다면 아무도 상품을 못 받는 사고가 난다.)

## 개발

```bash
nvm use              # Node 22
npm install
npm run dev          # http://localhost:5173
npm test             # 단위 + 흐름 테스트
npm run coverage     # 커버리지 80% 임계값 강제
npm run build        # tsc -b && vite build — Vercel이 실행하는 것과 동일
npm run preview      # 빌드 산출물 확인
```

**푸시 전에 반드시 `npm run build`가 로컬에서 통과해야 한다.** Vercel이 돌리는 명령과 같으므로,
여기서 깨지면 배포도 깨진다.

### 구조

```
src/
├── config.ts              부스 설정 + URL 파라미터 파싱
├── data/
│   ├── types.ts           Question 스키마
│   ├── questions.ts       36문항 (6 카테고리 × 6)
│   └── validateBank.ts    길이·정답분포·커버리지 검증
├── lib/
│   ├── shuffle.ts         Fisher-Yates (rng 주입 가능)
│   ├── pickSession.ts     카테고리 분산 + 난이도 오름차순 출제
│   └── grade.ts           등급/배너 문구
├── state/
│   ├── quizReducer.ts     순수 상태 기계 (연타 방지 가드 포함)
│   └── useQuiz.ts         랜덤은 여기서만 발생
├── hooks/useIdleReset.ts  무입력 자동 리셋
├── screens/               Start / Quiz / Result
└── components/            표현용 컴포넌트
```

랜덤을 리듀서 밖으로 뺀 덕분에 리듀서가 순수 함수이고, `pickSession`은 rng를 주입받아
200개 시드로 불변식(카테고리 분산·난이도 오름차순·주제 중복 없음)을 검증한다.

### 문제 추가하기

`src/data/questions.ts`에 추가하면 된다. `validateBank`가 아래를 강제한다:

- 문제 **60자** / 보기 **24자** / 해설 **70자** 이하 — 콘텐츠 규칙이 아니라 **레이아웃 규칙**이다.
  넘기면 폰에서 스크롤이 생기고, 부스에서 스크롤은 곧 이탈이다.
- 문제는 물음표로 끝날 것
- `choice`는 보기 4개, `ox`는 정확히 `['O', 'X']`
- 카테고리마다 난이도 1/2/3이 각각 최소 1문항
- 정답이 한 자리(A~D)에 40% 넘게 몰리지 않을 것

`npm test`가 실제 문제 은행을 검증하므로, 규칙을 어기면 테스트가 깨진다.

## 배포 (Vercel)

프론트는 Vercel 정적 호스팅. 백엔드가 없으므로 환경 변수도 없고 `vercel.json`도 필요 없다.
(라우터를 쓰지 않는 상태 기계라 SPA rewrite가 필요 없다.)

### 최초 설정

| 항목 | 값 |
|---|---|
| Project Name | `ausg-aws-quiz` |
| Framework Preset | Vite (자동 감지) |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm ci` |
| Node.js Version | **22.x** |

1. https://vercel.com/new → Import Git Repository
2. 레포가 목록에 없으면 **Adjust GitHub App Permissions** → `AUSG/ausg-aws-quiz` 접근 허용
   - ⚠️ **조직 레포라 org owner 승인이 필요할 수 있다. 행사 전날이 아니라 지금 걸어둘 것.**
3. Project Name을 `ausg-aws-quiz`로 지정 → Deploy

### 비상용 CLI 채널 (행사 전에 한 번 해둘 것)

GitHub App 승인이 막히거나 행사장에서 급하게 고쳐야 할 때를 대비한다.

```bash
npm i -g vercel
vercel login
vercel link --yes --project ausg-aws-quiz
vercel --prod        # GitHub 거치지 않고 로컬에서 바로 배포
```

### URL 주의

Vercel은 세 종류의 주소를 준다. **QR과 인쇄물에는 반드시 짧은 주소만 쓸 것.**

| 주소 | 쓸 것인가 |
|---|---|
| `ausg-aws-quiz.vercel.app` | ✅ 항상 최신 운영 버전 |
| `ausg-aws-quiz-git-main-*.vercel.app` | ❌ 브랜치 주소 |
| `ausg-aws-quiz-<hash>-*.vercel.app` | ❌ **배포마다 고정** — 인쇄하면 영원히 옛날 빌드가 뜬다 |

커스텀 도메인은 불필요하다. 아무도 URL을 타이핑하지 않고 QR을 찍는다.

### 롤백

Vercel 대시보드 → Deployments → 직전 정상 배포 → **Instant Rollback**. 재빌드 없이 수 초.
CLI로는 `vercel rollback <deployment-url>`.

> ⚠️ **서비스 워커 주의**: 오프라인 대응 때문에 PWA 캐시를 쓴다. CDN은 즉시 롤백되지만
> 부스 기기는 캐시된 옛 버전을 계속 띄울 수 있다. **배포/롤백 후에는 부스 기기를 강력 새로고침할 것.**
> (iOS Safari: 탭 닫고 재접속 / 데스크톱: DevTools → Application → Unregister service worker)

## 행사 당일 런북

### 기기 세팅 (공용 태블릿/노트북)

- [ ] **행사 시작 전에 페이지를 미리 열어둘 것.** 캐시가 채워지면 그 뒤로 wifi가 죽어도 계속 돌아간다.
- [ ] 비행기 모드로 바꿔서 **오프라인 동작 확인** (PWA 캐시 검증)
- [ ] iPad: 설정 → 손쉬운 사용 → **가이드 접근(Guided Access)** 켜기 (측면 버튼 3번 클릭)
- [ ] Android: 화면 고정 / 노트북: `chrome --kiosk --app=https://ausg-aws-quiz.vercel.app`
- [ ] 자동 잠금 끄기, 방해금지 모드 켜기, 화면 회전 잠금, 밝기 최대
- [ ] **충전기 연결.** 밝기 최대로 8시간이면 배터리로는 못 버틴다
- [ ] OS·앱 자동 업데이트 하루만 끄기

### 사전 준비

| 시점 | 할 일 |
|---|---|
| D-7 | Vercel GitHub App **org 승인** 완료, 첫 배포 성공 확인 |
| D-2 | 문제 내용 확정(콘텐츠 프리즈). QR을 **짧은 운영 URL**로 생성 후 폰 3대(iOS 카메라 / 안드로이드 / 카톡 인앱 스캐너)에서 테스트 |
| D-1 | `vercel` CLI를 부스 노트북에 설치·로그인. 휴대폰 핫스팟 준비하고 모든 기기를 미리 연결·신뢰 처리 |
| D-0 (1시간 전) | 직전 정상 배포 주소를 폰 메모에 적어둘 것(롤백 대상). 키오스크 모드 켜기. **`main` 브랜치 동결** |

### 최후의 수단 — 인터넷이 완전히 죽었을 때

빌드가 경로에 독립적(`base: './'`)이라 부스 노트북에서 그대로 띄울 수 있다.

```bash
npm run build
npx serve dist        # 이 노트북에서 로컬로 서비스
```

### 진행 중 규칙

- **`main`에 직접 푸시 금지.** Git 연동이라 푸시가 곧 운영 배포다.
- 급한 수정은 브랜치 → 프리뷰 URL에서 확인 → 승격.
- 뭔가 이상하면 고치려 들지 말고 **먼저 롤백**하고 나중에 원인을 본다.

## 상품 등급

스태프는 배너 **색**만 보면 된다. 숫자를 읽을 필요가 없다.

| 점수 | 배너 | 색 | 조치 |
|---|---|---|---|
| 5/5 | 🏆 만점! 특별 상품 받아가세요! | 금색 | 특별 상품 |
| 4/5 | 🎁 스티커 받아가세요! | 초록 | 스티커 |
| 3/5 이하 | 🙌 참여해주셔서 감사합니다! | 회색 | 없음 |

> 재도전 방지 장치는 없다(의도된 것). 부스에서 반복 참여를 막는 건 기술이 아니라
> 옆에 서 있는 스태프의 몫이다. 상품이 정말 값나가면 스태프가 일회용 교환권을 나눠주는 쪽이 맞다.
